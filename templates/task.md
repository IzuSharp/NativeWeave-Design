## Goal, inputs, and outputs
Define a narrowly scoped deliverable; do not merely write “implement ORM”.

## Paths permitted/prohibited for changes
List exact repository paths; use integration requests for shared files rather than having multiple tasks write broadly to src/** concurrently.

## Implementation basis
Candidate types/interfaces, normal paths, error paths, and resource/concurrency rules; replace these with accepted contracts before formal work begins.

## Verification and failure criteria
Unit/integration tests, actual Windows/Linux execution, Native AOT, fault/property/fuzz testing or formal methods, and workload performance; explain anything not applicable.

## Delivery
Code, tests, documentation, raw evidence, an independent PR, and review of the exact commit; describe rules for partial delivery, failure, and revalidation.

## Completion
Satisfy all evidence and review requirements for the task. This template cannot automatically promote a candidate task to accepted.
