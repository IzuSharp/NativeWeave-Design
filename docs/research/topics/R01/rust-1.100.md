## 2. Adopt, retain or defer

| Mechanism | Source/real compiler result | NativeWeave disposition |
|---|---|---|
| Never `!` | Stable in ordinary type positions; `Infallible` now aliases `!`; fixture runs and old dual-impl negative fails E0119 | Use for internal impossible failure states where clearer. Do not export Rust enum/never layouts through C ABI. Audit aliases/coherence and fallback across editions. |
| `Allocator`, `Vec<T,A>`, `Box<T,A>` core APIs | Stable allocator trait and owner-aware core constructors/raw parts compile and run | Allow small Engine-local allocation/budget wrappers where measured useful. Retain allocator identity and lifetime in native owners; never free with another CRT/allocator. No required framework-wide allocator. |
| Allocator extensions | `Arc::new_in` fails E0658 on stable1.100; allocation extension APIs are not all stabilized | No nightly feature or assumption that every allocator-aware standard-library API is stable. `Arc<A>: Allocator` delegation to a stable Vec is separately supported and tested. |
| `DropGuard` | Stable ordinary runtime API; normal/drop/unwind/dismiss fixtures pass | Replace redundant **local synchronous rollback guards** where equivalent. Never replace async close, callback quiescence, pool recovery, body retirement or native module leases. |
| `Box::map` | Stable; equal-layout reuse and different-layout reallocation/panic cleanup observed | Useful for private pre-publication transitions. Do not promise stable addresses or transform a published FFI object's identity. `Box::try_map` remains unstable. |
| `Arc::map` / `Rc::map` | Stable map; Arc takes a borrowed input to its closure, consumes one Arc; uniqueness/layout determine reuse | Optional private immutable transformations. Not shared in-place mutation. Weak/shared holders and concurrency invalidate simplistic allocation assumptions. |
| `Vec::from_fn` | Stable; implemented by iterator collection; zero count/order/panic cleanup tested | Concise trusted-size initialization. Not a fallible or allocation-free builder. Retain checked `try_reserve` and explicit construction for adversarial lengths/budgets. |
| `extern "custom"` | Stable for custom naked/assembly contracts; normal body rejected, naked fixture compiles without being called | **Do not use for P/Invoke.** Keep `extern "C"`/explicit agreed convention. Custom is not a faster C ABI. |
| `-Cprofile-sample-use` | Stabilization in release notes; no optimization benchmark executed | Optional later PGO experiment with real representative workloads and profile provenance. No default flag, numerical speedup or distributed `target-cpu=native`. |
| Cargo unused dependencies | Stable lint; unused local dependency rejected, used dependency passes | Enable for owned crates in appropriate feature/target CI. Do not automatically remove feature-activation/version pins or claim all dev-dependencies are covered. |
| Cargo build-dir/cache | New intermediate layout; real JSON artifact discovery succeeds on both OS | Stop deriving artifacts from `deps`/fingerprint directory guesses. Separate final target assets from per-worktree intermediate caches, resolve Cargo JSON output. |
| Cargo min-publish-age | Stable resolver policy, locked-version exception and source behavior inspected | Adopt configurable maintainer dependency-update cooldown with explicit emergency audit. Not a vulnerability scanner, signature check or retroactive lockfile audit. |

## 3. Allocation and ownership source chain

At the fixed Rust commit, [`library/core/src/alloc/mod.rs`](https://github.com/rust-lang/rust/blob/0ef1bc386059596dada8fb65b50425aab2ea637a/library/core/src/alloc/mod.rs#L105-L335) specifies allocation validity, allocator cloning/moving, pointer/layout requirements and grow/shrink ownership. The allocator methods **and its Drop implementation must not unwind**. A failed grow keeps the original block owned and unchanged. Successful grow invalidates the old pointer even if the returned address is numerically equal. Allocation may return Err, but an infallible collection constructor can still invoke allocation-error handling; `catch_unwind` is not an OOM guarantee.

NativeWeave must retain the allocator owner for as long as any buffer or lease can release its allocation. A C# SafeHandle denotes that native owner; exposing a byte pointer does not export the allocator itself. A native release operation carries enough typed owner information to select the original deallocation path. `Vec::into_raw_parts_with_allocator` includes pointer, length, capacity and allocator; reconstructing with another allocator/layout or twice is invalid. No CLR `NativeMemory.Free`, Rust Global or Windows CRT equivalence is inferred.

`Vec<T,A>` only redirects that collection's backing allocation. Nested String/Vec/Arc values and SeaQuery/Tokio/SQLx internals may still use their own allocators. Therefore wrapping an outer result vector does **not** impose an Engine-wide or process-RSS ceiling. Avoid adding a global allocator/runtime simply because the stable trait is now available. Memory admission still needs logical bytes, live owner/queue accounting and measured allocator/runtime overhead. A fallible wrapper's counters must use a non-panicking, concurrency-correct policy; the fixture's single-thread Cell counter is deliberately not production accounting.

[`library/alloc/src/boxed.rs:680–752`](https://github.com/rust-lang/rust/blob/0ef1bc386059596dada8fb65b50425aab2ea637a/library/alloc/src/boxed.rs#L680-L752) shows Box::take retaining allocation as MaybeUninit and Box::map checking size/alignment before reuse. The other branch drops the old allocation and allocates for the transformed type; panic paths remain owned. This can replace custom raw-pointer mapping glue **inside Rust**, not validate a published object's aliasing or Pin contract. The fixture's pointer equality is an observation at this exact pin, not an ABI guarantee.

[`library/alloc/src/sync.rs:1200–1285`](https://github.com/rust-lang/rust/blob/0ef1bc386059596dada8fb65b50425aab2ea637a/library/alloc/src/sync.rs#L1200-L1285) reuses for equal size/alignment and `Arc::is_unique`. [`is_unique:2929–2950`](https://github.com/rust-lang/rust/blob/0ef1bc386059596dada8fb65b50425aab2ea637a/library/alloc/src/sync.rs#L2929-L2950) locks the weak count and checks strong ownership with acquire/release synchronization. A separate `strong_count()==1` precheck is not an equivalent proof. `Arc::map` gives its closure `&T`, not ownership of every shared T, and produces an independent result when needed. A Weak to the original value does not become a Weak to the mapped result. Do not use this as an operation on live exported callback/session handles. Rc has the analogous non-atomic ownership concern and is not made Send by mapping.

## 4. Cleanup and impossible states

The complete [`library/core/src/mem/drop_guard.rs`](https://github.com/rust-lang/rust/blob/0ef1bc386059596dada8fb65b50425aab2ea637a/library/core/src/mem/drop_guard.rs) stores value and closure in ManuallyDrop. Drop takes both and calls the FnOnce. `dismiss` takes the value and drops the stored closure; it deliberately avoids leaking captured resources. Its extraction order ensures the value can unwind safely even if destroying a closure capture panics. Ordinary APIs are stable while several const-use aspects remain marked const-unstable; do not infer const stabilization.

Upstream [`library/coretests/tests/mem.rs:777–822`](https://github.com/rust-lang/rust/blob/0ef1bc386059596dada8fb65b50425aab2ea637a/library/coretests/tests/mem.rs#L777-L822) tests run/dismiss/destructor-panic behavior; those upstream tests were **read, not run** here. Our separate normal/dismiss/capture-drop/unwind fixtures actually ran. A guard can be forgotten; process abort skips ordinary unwinding; a second panic during unwinding can abort. A guard action crossing the ABI must be non-panicking and non-blocking. Dropping a Future only runs its synchronous destructor; it does not prove remote cancellation, database rollback acknowledgment, worker exit or callback silence.

`Infallible` is now a type alias to `!` in [`core/src/convert/mod.rs`](https://github.com/rust-lang/rust/blob/0ef1bc386059596dada8fb65b50425aab2ea637a/library/core/src/convert/mod.rs). Code with separate impls for `fn()->!` and `fn()->Infallible` now overlaps. NativeWeave's fixture confirms E0119 and confirms type use in editions2024/2021. The fallback change applies to all editions. Keep explicit types at unsafe/FFI inference boundaries instead of relying on historical unit fallback. Existing stable `MaybeUninit`, `NonNull`, fixed-width fields, repr(C), unsafe extern/no_mangle attributes and `unsafe_op_in_unsafe_fn` remain the baseline; new syntax does not replace their safety obligations.

[`compiler/rustc_abi/src/extern_abi.rs:60–64`](https://github.com/rust-lang/rust/blob/0ef1bc386059596dada8fb65b50425aab2ea637a/compiler/rustc_abi/src/extern_abi.rs#L60-L64) describes Custom as an ABI rustc does not know how to call/define normally: naked definitions or custom extern blocks, calls from assembly. A compile-only ret fixture is not a validated calling convention, unwind path or C# binding. NativeWeave continues to use C ABI.

## 5. Cargo implementation, limits and actionable build changes

Cargo source has moved/reorganized; at the pinned Cargo commit the implementations are under `src/diagnostics`, `src/compiler`, `src/resolver`, etc., and the book is `doc/book`. Initial collection missed old assumed paths; those omissions are not represented as inspected code.

[`src/diagnostics/rules/unused_dependencies.rs`](https://github.com/rust-lang/cargo/blob/3acc79c0c841844675bc53a605922dbfc441e750/src/diagnostics/rules/unused_dependencies.rs) checks package/target coverage, waits for needed compilation units and suppresses transitive feature-activation cases. Its documented limitations include selected packages only and unchecked dev-dependency coverage. Enable `[lints.cargo] unused_dependencies="deny"` for owned packages with deliberate feature/target coverage and documented exceptions; do not apply it blindly as a complete dependency audit. The executed path-dependency negative/positive fixture proves actual stable lint behavior, not coverage of every Cargo edge case.

[`src/resolver/version_prefs.rs:173–310`](https://github.com/rust-lang/cargo/blob/3acc79c0c841844675bc53a605922dbfc441e750/src/resolver/version_prefs.rs#L173-L310) snapshots invocation time, parses global/per-registry age, and compares publish time. A registry-specific setting overrides the global one. An explicit zero disables that scope. The inspected `too_new` returns no violation when publish-time metadata is missing; this is not a fail-closed authenticity check. The [resolver book](https://github.com/rust-lang/cargo/blob/3acc79c0c841844675bc53a605922dbfc441e750/doc/book/src/reference/resolver.md#L313-L325) explicitly exempts versions already in Cargo.lock. An allow override permits too-new resolutions and must be documented for a security fix, not enabled by default. [`tests/testsuite/min_publish_age.rs:1–210`](https://github.com/rust-lang/cargo/blob/3acc79c0c841844675bc53a605922dbfc441e750/tests/testsuite/min_publish_age.rs#L1-L210) contains mocked registry/time tests; inspected, not executed here.

Recommended maintainer policy: use a configurable **7-day dependency-update cooldown as an engineering policy choice**, not a claim that seven days guarantees security. Lock release inputs and use `cargo build/test --locked`; separately review advisories, provenance, checksums/licenses and necessary emergency updates. The release's cargo-install lockfile default change does not make `--locked` unnecessary for build/test. Already locked malicious dependencies are not removed by min-publish-age.

The [build-cache book](https://github.com/rust-lang/cargo/blob/3acc79c0c841844675bc53a605922dbfc441e750/doc/book/src/reference/build-cache.md) separates final target-dir from intermediate build-dir and declares intermediate layout unstable. The [configuration](https://github.com/rust-lang/cargo/blob/3acc79c0c841844675bc53a605922dbfc441e750/doc/book/src/reference/config.md#L566-L584) supports workspace-root, cargo-cache-home and workspace-path-hash templates. Use isolated per-worktree intermediate paths plus keyed CI caches (toolchain/host/target/features/profile/lockfile), and Cargo JSON compiler-artifact filenames for NuGet native assets. A workspace hash isolates paths; it is not proof of cross-worktree cache reuse, lack of lock contention or cache trust. No cache speedup was measured.

## 6. Database, Server and compatibility impact

The captured official registry observations still identify SeaQuery1.0.2, SeaORM2.0.4, SQLx0.9.0, Tokio1.54.1, Hyper1.12.0, hyper-util0.1.21, Tower0.5.3, Axum0.8.9, Actix Web4.19.0, Actix Server2.10.0 and Pingora0.9.1 as newest stable/non-yanked candidates. `sea-query-sqlx` is0.9.1 in this observation and must not be confused with SeaQuery's version. Metadata declares MSRV1.94 for SQLx/SeaORM/binder,1.88 for SeaQuery; Pingora has no rust_version in this metadata. Full feature/target dependency closure compilation remains a separate gate; being below1.100 in MSRV is not a proof of compatibility.

No package is upgraded merely because rustc changed. Preserve existing locks and source comparisons. Rust1.100 does not turn SeaORM's static Entity types into runtime types; its actual dynamic module remains a distinct, unstable interface whose public construction/CRUD boundaries were studied in the R25 addendum. It does not eliminate SeaQuery's backend capability checks, binder narrowing/error handling or SQLx transaction uncertainty. New allocation APIs do not retrofit generic allocators into those upstream ASTs. The precompiled runtime-metadata/typed Fluent architecture remains valid without a complete C# query engine.

For Server, new DropGuard/map APIs may simplify private admission rollback/immutable metadata, not erase native Service/Body/Task completion boundaries. Tower's response-future permit still does not cover body lifetime; H2 flow credit still does not reclaim bytes retained on the managed side. No new global Tokio runtime or allocator is justified. Actix Rc/thread-affine resources remain thread-affine. Next R27 fixture must exercise actual native Service/Body behavior, not only the existing abstract model.

Compatibility checks retained: changed never fallback and Infallible coherence; Box allocator type inference; more precise closure capture and dyn-compatibility diagnostics; duplicate repr/packed-align lints; Rust ABI changes do not authorize using Rust ABI across DLLs; ARM ABI-changing target flags fail; i686 Windows GNU host-tool downgrade is not all Windows target removal. Formal initial target candidates remain linux-x64 and win-x64, with their own AOT/link tests. Unicode18 or changed Ord method calls can affect inconsistent custom implementations and require semantic tests where relevant. Profile-sample-use is available, not adopted before workload evidence.
